Chapter 6 Slash commands — 打 / 主動使用

⏱ 預估 8 分鐘讀完,加上小練習共 20 分鐘

💡 一句話講完

slash command 是主動觸發方式(打 /)。/ 叫得出來的東西本質分兩類:內建邏輯指令(/compact 這種改不了)和 skill(一份讓 Claude 編排的指示)。skill 底下再按來源分官方內建和你自訂。

基本用法

在 session 裡打 / 就會列出所有可用的指令,繼續打字可以過濾。兩個規則:

  • 指令只在訊息開頭會被認得 — 訊息中間出現的 /xxx 只是普通文字。
  • 指令名稱後面的文字會當作參數(arguments)傳給它,例如 /compact 重點保留測試結果。

本質分兩類:內建指令 vs skill

1. 內建指令:行為寫死在 CLI 裡

這類指令的邏輯直接寫在 Claude Code 程式裡 — 固定流程、一定那樣跑、你改不了。它不經過 Claude 的判斷,跟模型無關。官方清單將近 90 個,以下按使用情境挑常用的介紹:

每天都會碰到的

指令用途
/clear開新對話、context 歸零。換任務就清,別讓上個任務的脈絡污染下一個。舊對話留在 /resume 裡,還能 /clear 修登入bug 順手幫舊對話取名
/compact把對話摘要壓縮,釋放 context 但保留重點,可指定方向:/compact 重點保留測試結果。跟 /clear 的差別:/clear 是斷捨離,/compact 是瘦身續用
/context把 context 用量畫成色塊圖,看 token 被誰吃掉(工具輸出?CLAUDE.md 太肥?)。覺得 Claude 變鈍時先看這個
/resume回到之前的對話(開選單挑,或直接給名字/ID)。別名 /continue
/rewind後悔藥:把對話和/或程式碼回捲到先前的 checkpoint。Claude 改壞東西時用。別名 /undo

改 Claude 行為的

/model切換模型,會存成之後 session 的預設

/plan進 plan mode:Claude 先提計畫、你核准了才動手。大改動前用,可帶任務描述:/plan 重構付款流程
/btw問個小問題但不寫進對話歷史,不污染 context。例如做到一半想問「git stash 怎麼用」

2. skill:一份讓 Claude 編排的指示

跟內建指令相反,這類東西的本體是 prompt — 把一份詳細指示交給 Claude,讓它用自己的工具去編排執行,所以同一個 skill 每次跑的過程可能不完全一樣。按來源分兩種:

  • 官方內建(bundled):Claude Code 自帶、每個 session 都可用,例如 /code-review(程式碼審查)、/debug(疑難排解)、/loop(重複執行)、/run / /verify(啟動 app 驗證改動)。在官方指令清單裡會標 Skill 字樣。
  • 你自訂:就是 Chapter 5 教的 skill,放在專案的 .claude/skills/(或個人的 ~/.claude/skills/)底下,建好就多一個 / 指令。

自訂 skill 的結構

.claude/skills/
└── explain-file/        ← 資料夾名 = 指令名(/explain-file)
    └── SKILL.md         ← 檔名固定,一定叫 SKILL.md(大寫)
   (可選)scripts/ 等     ← 支援檔案隨你加,名字隨你取
  • 檔名固定是 SKILL.md:這是入口檔、必須存在。其他檔案(範本、腳本、參考資料)隨你加,但 Claude 是從 SKILL.md 開始讀的。
  • 指令名來自資料夾名,不是 frontmatter 的 name(name 只影響清單裡的顯示名稱)。所以 .claude/skills/deploy-staging/SKILL.md → /deploy-staging。
內建指令skill
本體 寫死在 CLI 的程式邏輯 一份 prompt(指示)
執行者 Claude Code 程式本身 Claude(讀指示後自己編排)
能不能改 不能 bundled 不能改但可停用;自訂的隨你寫
觸發方式 只能你打 / 你打 /,或 Claude 自動叫用

傳參數:$ARGUMENTS

指令名稱後面打的文字,可以在 skill 內文裡用佔位符接住:

佔位符意思
$ARGUMENTS整串參數(照你打的原樣)
$0、$1…第 1、第 2 個參數(空白分隔;要包含空白就加引號)

官方文件的例子 — 修 GitHub issue 的 skill:

---
name: fix-issue
description: Fix a GitHub issue
---

Fix GitHub issue $ARGUMENTS following our coding standards.

執行 /fix-issue 123,Claude 收到的就是「Fix GitHub issue 123 following our coding standards.」— $ARGUMENTS 在 Claude 看到內容之前就被換成你打的字了。如果 skill 內文沒寫 $ARGUMENTS,參數會自動以 ARGUMENTS: <你打的字> 附加在最後,Claude 一樣看得到。

另外,frontmatter 的 argument-hint 可以在 / 自動補全時提示要帶什麼參數,例如 argument-hint: [issue-number]。

🛠 小練習:建一個「只能手動觸發 + 吃參數」的自訂 command

步驟

  1. 在專案裡建一個 skill 檔 .claude/skills/explain-file/SKILL.md(直接手寫,或請 Claude 幫你建):
    2. ---
description: 解釋指定檔案在做什麼
argument-hint: [檔案路徑] [想了解的重點]
disable-model-invocation: true
---

請閱讀 $0,用三點以內解釋它在做什麼。
特別針對這個重點說明:$1
  2. 打 / 再打 ex 過濾,確認清單出現 explain-file,而且後面帶著 [檔案路徑] [想了解的重點] 的參數提示(這就是 argument-hint)。
  3. 帶參數執行(第二個參數有空白,所以加引號):
    4.  /explain-file cmd內的文件 "是怎麼運作的"
  4. 觀察 Claude 的回應:它收到的指示裡 $0 已經被換成 cmd內的文件、是怎麼運作的 換成你引號裡的那句話。

練習目的

  • 看到 $0 / $1 / $ARGUMENTS 參數替換真的發生
