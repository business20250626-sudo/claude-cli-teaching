Chapter 7 MCP servers — 接上外部工具的標準

⏱ 預估 10 分鐘讀完,加上小練習共 25 分鐘

💡 一句話講完

MCP(Model Context Protocol)是讓模型接上外部工具 / 資料的開放標準 — 官方的比喻是「AI 界的 USB-C」。工具提供方把用法包成一個 MCP server、只包一次,任何會講 MCP 的 agent 插上就能用;接上之後你只管下任務,Claude 在工作時自己判斷該呼叫哪個工具。

為什麼需要它:從「各接各的」到「包一次、到處插」

想像 USB-C 出現之前的世界:每台裝置一種接頭,出門要帶一袋轉接線。只有 API 的年代就是這樣 — 工具只給你一份 API 文件,每個想讓 agent 用它的人,都得自己讀文件、自己定義用法、自己寫接線塞給自己的 agent。十個團隊接同一個服務,同一條線就被重寫十次;agent 一多、工具一多,接線數量是相乘地長。

MCP 把接頭統一了:改由工具提供方把「怎麼用我」包裝成一個 MCP server — 有哪些工具、各吃什麼參數、回傳什麼,全部包好,只包一次。任何會講 MCP 的 agent(Claude Code、ChatGPT、Cursor⋯)執行時掛上就能用,官方原話就是「build once and integrate everywhere」。對你來說,Claude Code 因此能直接接上數百種現成的外部工具和資料源。

而且接上之後的體驗也不一樣:你不是「呼叫工具」,而是「下任務」 — server 把每個工具的用途描述好了,Claude 看著你的任務,自己挑、自己呼叫、自己串。

🔗 跟 Skill 的分工

容易搞混的對照:skill 給 Claude 的是「指示」(教它怎麼做事的知識),MCP 給 Claude 的是「工具」(它原本根本碰不到的外部系統)。skill 教做法、MCP 長出新的手,兩者常常搭配:一個 skill 的步驟裡可能就會用到 MCP 工具。

怎麼接:claude mcp add

先建立一個觀念:MCP server 是一支程式,它總得在某個地方跑。跑在哪,決定你用哪種方式接:

遠端 HTTP server(程式跑在提供方的雲端,官方推薦)

像 Notion 把 server 架在他們自己的機器上,你只要給 Claude Code 一個 URL,之後每次用工具就是發 HTTP 請求過去。你的機器上什麼都不用裝。雲端服務(Notion、GitHub、Sentry)幾乎都是這種:

# 基本語法
claude mcp add --transport http <名稱> <URL>

# 官方範例:接 Notion
claude mcp add --transport http notion https://mcp.notion.com/mcp

本機 stdio server(程式跑在你的電腦上)

這種 server 是一支由 Claude Code 親自啟動的本機程序:兩支程式用 stdin / stdout(標準輸入輸出)對話 — stdio 這名字就是這麼來的,完全不走網路。所以你給的不是 URL,而是一條啟動指令 — -- 分隔符前面是 Claude Code 自己的選項,後面整串就是它替你執行的指令:

# 基本語法:-- 後面是「怎麼把這支 server 跑起來」
claude mcp add [選項] <名稱> -- <指令> [參數...]

它存在的理由:有些東西只有你的機器碰得到 — 內網服務、本機檔案,以及最值得記住的場景:自製工具。想像把公司內部 API 包成一支 MCP server(可以請 Claude 幫你寫),跑在每個人本機,設定 commit 進 repo — 全隊每個人的 Claude 從此都查得到內部系統。

遠端 HTTP本機 stdio
server 程式跑在哪 提供方的雲端 你的電腦(Claude Code 替你啟動)
你提供什麼 一個 URL 一條啟動指令(-- 後面那串)
溝通方式 HTTP 請求(走網路) stdin / stdout(不走網路)
典型場景 雲端服務(Notion、GitHub、Sentry) 只有本機碰得到的東西、公司內部 API 等自製工具

實務上不用背:看工具的 README 給你的是 URL 還是啟動指令,給什麼就用什麼。

接好之後的管理

claude mcp list      # 列出所有設定好的 server
claude mcp get notion   # 看某個 server 的細節
claude mcp remove notion  # 移除

/mcp                 # (session 內)看連線狀態、各 server 的工具數、OAuth 登入

遠端 server 多半要登入授權:打 /mcp,挑那個 server,它會開瀏覽器走 OAuth 流程,跟你平常「用 Google 登入」一樣。

⚠️ 安全:接之前先想兩件事
  • 信任來源:官方文件的警告 —「接每個 server 之前,先確認你信任它。會抓外部內容的 server 可能讓你暴露在 prompt injection 風險中。」(惡意內容混進 Claude 看到的資料裡,引導它做不該做的事)
  • 金鑰不落地:API key、token 不要直接寫進會 commit 的 .mcp.json — 它支援 ${VAR} 環境變數展開,repo 裡只放佔位符,真正的 key 各自放在自己的 shell 環境(~/.zshrc 裡 export)。另外注意:在 claude mcp add 指令列直接打真 key,那行指令會連 key 一起留在 shell 歷史紀錄裡,個人用勉強可以,但別養成習慣。
🛠 小練習:接 Notion 官方 MCP server,看 Claude 自己挑工具

步驟

  1. 用官方文件的指令接上 Notion 的遠端 HTTP server(只要給 URL,什麼都不用裝):
    2. claude mcp add --transport http notion https://mcp.notion.com/mcp
  2. 開 Claude Code,打 /mcp,挑 notion 完成 OAuth 登入 — 它會開瀏覽器讓你授權,跟「用 Google 登入」一樣。授權完回到 /mcp,確認 notion 顯示已連線,旁邊列出它提供了幾個工具。
  3. 用自然語言下任務 — 注意你完全沒指定要用哪個工具:
    4. 列出我 Notion 裡最近編輯的幾個頁面
  4. 觀察 Claude 的執行過程:它自己從 Notion server 的工具裡挑了對的那個(會看到類似 mcp__notion__... 的工具呼叫)— 這就是「agent 工作時自己判斷該呼叫哪個」。
  5. (收尾,可選)練習完不想留著就移除:claude mcp remove notion。

練習目的

  • 走一次完整流程:加 server → /mcp OAuth 登入 → 自然語言使用
  • 親眼看到「你不指定工具,Claude 自己判斷呼叫哪個」
